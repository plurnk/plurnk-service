# @plurnk/plurnk-parser — SPEC

## §parser-boundary Public entry points, path decomposition, and CLI

`@plurnk/plurnk-parser` owns lowering, statement parsing, canonical serialization, target decomposition, and the `plurnk-parser` CLI implementing `@plurnk/plurnk-contracts` ({§mcp-expressions}, {§path-syntax}):

| Entry point | Signature & input | Return & contract |
| --- | --- | --- |
| `PlurnkParser.lowerMcpCall(call, options?)` | Wire `{ name, arguments }` + `LowerToolCallOptions` (`executors`, `aside`, `tier`, `position`) | `ParseResult` (`items` of `{ kind: "statement", statement }` and `{ kind: "error", error, attempt? }`); defaults to `"model"` tier recovery ({§parse-recovery}, {§parser-lowering}). |
| `PlurnkParser.lowerToolCall(service, tool, args?, options?)` | Inbound `/mcp` `(service, tool, args?)` + `LowerToolCallOptions` | `ParseResult` lowered through the shared call dispatcher; defaults to `"statements"` tier. |
| `PlurnkParser.parseStatements(input, options?)` | Client or internal `<server>.<tool>(...)` statement source + `ParseOptions` (`executors`) | `ParseResult` over statement blocks and trailing comments/asides ({§expression-boundaries}). |
| `PlurnkParser.toMcpCall(statement)` | One `PlurnkStatement` AST node | Canonical `McpToolCallPayload` (`{ server, tool, arguments, aside? }`) for `assistant` `toolCalls` replay. |
| `PlurnkParser.stringify(statements)` | `readonly PlurnkStatement[]` | Blank-line-separated `<server>.<tool>({}) // aside` source lines for `ops://` reflection. |
| `PlurnkParser.NO_VALID_EXPRESSION` | Constant diagnostic string | `"No valid MCP tool calls detected."` sentinel for empty/unparsed wire tool-call turns. |
| `parsePath(raw, pos?)` | Single target path or URI string | `null` on `""`, `{ kind: "local", raw, fragment? }` on bare paths, or WHATWG-decomposed `UrlPath` preserving brace globs (`PlurnkParseError` on invalid URI, {§path-syntax}). |
| `targetMembers(raw, options?)` | Authored target string | Splits top-level multi-target groups while preserving brace/bracket/paren globs and escaped delimiters ({§slot-order}). |
| `plurnk-parser [file]` | File path, `-` / omitted `stdin`, or `--help` | Prints `PlurnkParser.parseStatements` JSON (`RegExp` rendered via `.toString()`); exits `0` when error-free, `1` on any parse error. |

### §expression-boundaries Wire tool lowering, standalone runtime routing, and replay projection

| Rule | Contract |
| --- | --- |
| `lowerMcpCall` envelope lowering | `PlurnkParser.lowerMcpCall({ name, arguments }, options)` requires `name === "mcp"`, decodes object or JSON-stringified `arguments`, resolves `server` and `tool` (tolerating `function` for `tool` and `args`/`params` or hoisted sibling keys for `arguments`), and dispatches to `lowerToolCall` on the `"model"` tier. |
| Standalone runtime default tool | Passing `server: "sh" \| "js" \| "python3"` (or a built-in alias `bash`/`shell` $\to$ `sh`, `ts`/`javascript`/`typescript`/`node` $\to$ `js`, `python`/`py` $\to$ `python3` when not shadowed by an explicit executor) routes any non-path `tool` name directly to that standalone runtime (`text` / `command` / `code`), while path-shaped `tool` names (`*.py`, `dir/script.sh`) bind `script`. |
| Case-insensitive method recovery | Uppercase or mixed-case core/runtime tool names recover silently to their lowercase canonical tool name. |
| Structured replay & `ops://` serialization | `PlurnkParser.toMcpCall(statement)` projects any `PlurnkStatement` to `{ server, tool, arguments, aside? }` for structured `assistant` `toolCalls` replay; `PlurnkParser.stringify(statements)` renders JSON-escaped canonical `<server>.<tool>({ ... }) // aside` lines for `ops://` storage. |

### §slot-order Argument shapes, target groups, and endpoint options

| Construct | Contract |
| --- | --- |
| Object and positional argument forms | Core operations accept their canonical `{ ... }` options object (`{ path, range?, pattern?, text?, ... }`) as well as positional shorthands on `parseStatements`. |
| Target groups and multi-target lists | `read`, `find`, and `kill` accept `path` or `paths` as a string or array of strings; comma/pipe/whitespace-separated `scheme://` URI lists and comma/pipe-separated local path/glob lists outside brackets/braces expand into one statement per target in authored order. `send`, `done`, and `fail` tolerate `target`/`targets`/`to` as a non-empty array of URI strings or comma/pipe-separated URI list (keeping message-reply URI lists on one statement so the body renders and weighs once, fanning out non-message `send` recipient lists per target, and refusing empty arrays or non-string targets at parse time rather than coercing to `null`; `work` and `fork` likewise refuse non-string targets). |
| `note` annotation on retrievals | Providing `note` on `read` or `find` emits a preceding `note` statement before the retrieval(s). |
| Endpoint and message options | `headers` (`Record<string, string>`) passes HTTP(S) request headers on `read`, `find`, `edit`, `send`, `kill`, and `copy`/`move` (`fromHeaders`/`toHeaders`); `remote` (`boolean`) confirms remote HTTP `DELETE` on `kill`; `attachments` (`string[]`) attaches resources to `send`, `done`, and `fail`. Unknown option keys (outside benign metadata and model-tier envelope/commentary echoes) are refused with a parser diagnostic. |
| Operation aside | `aside` on `mcp` tool calls (or trailing `// aside` on `parseStatements`, plus `description`/`explanation`/`comment`/`reason`/`what`/`why`/`intent` options on the model tier when `aside` is absent) is captured into `aside` (`string` or `null`). |

## §parser-lowering MCP call lowering, tier recovery, and canonical coercion

`McpExpressions`, `CallExpressionParser`, `OptionCoercion`, `StatementLowering`, `ScopeSyntax`, `MatcherSyntax`, and `ExpressionSerializer` share one deterministic lowering and coercion pipeline ({§mcp-expressions}, {§op-shapes}, {§matcher-prefix-claims}, {§parse-recovery}):

| Mechanism | Contract |
| --- | --- |
| Ambiguity boundary | Because `MCP_WIRE_TOOL` omits per-tool parameter schemas from `tools[]`, model-tier `lowerMcpCall` recovers inputs whose intended operation and operand mapping are unambiguous (replaying canonical `mcp` calls via `toMcpCall`), and refuses (`400`) cross-verb payload collisions, missing targets, or competing interpretations ({§diagnostic-observation}). Each malformed call emits at most one hard error (`operationOmitted: true`) with canonical `mcp(...)` `recovery`. |
| Wire envelope & target tolerances (`McpExpressions`, `StatementLowering`) | Canonicalizes near-miss wire tool names (`mcp__<server>__<tool>`, `<server>.<tool>`, `<server>__<tool>`, or bare `plurnk` tool/executor names), dotted `tool: "<server>.<tool>"` or omitted `server: "plurnk"`, bare `mcp({ text })` into `plurnk.note`, model-tier `plurnk.write` into whole-file `edit` (`range: "1,-1"` when unscoped), omitted `path` on model-tier `find({ pattern })` into `"**"`, 4-segment `log://<loop>/<turn>/<seq>/<op>` and `<sh\|js\|python3>:///<loop>/<turn>/<seq>/<op>` targets into `log:///`, nested tool calls routed through `plurnk.mcp`, DSML `<｜DSML｜parameter name="...">` and XML `<parameter=...>` / `<tool_call><function=...>` / trailing-`>` invoke-boundary leaks, nested parameter wrappers (`params`, `parameters`, `arguments`, `args`, `input`, `options`, `properties`), echoed `tool`/`function`, benign metadata (`tags`, `keep`, `kind`, `status`, `budget`, `maxLines`, `max_lines`, numeric/null `context` on `read`/`find`, redundant `context` on `edit`, numeric `before`/`after` on `read`/`find`, `occurrences: 1\|"1"` on `edit`), fallback `id` and `ids`/`streams` URI-array targets, `session`/`sessionId`/`stream`/`streamId`/`process`/`processId` on `kill`, `wait` `stream`/`streamId` and `timeoutMs`/`timeout_ms`/`ms`, `note` body fallback on `done`/`fail`/`wait`, model-tier `note` $\to$ `aside` coercion on `edit` and `kill`, inline `env` records on `sh`/`js`/`python3`, and separate `channel: "#<name>" \| "<name>"` options (folded onto fragmentless paths as `path#channel`). |
| Selection, edit & transfer tolerances (`OptionCoercion`) | Hoists selection keys (`range`, `lines`, `line`, `scope`, `region`, `limit`, `pattern`, `matcher`, `query`) and drops benign `case`/`context`/`before`/`after`/`maxLines` hints from non-HTTP `headers` (unwrapping `headers.headers`); promotes pattern-shaped and `#<channel>`-shaped `range` strings when `pattern`/`channel` are omitted; pairs integer line bounds (`startLine`/`start_line`/`start`/`from` and `endLine`/`end_line`/`end`/`to`); recovers `move`/`copy` source-destination aliases (`oldPath`/`old_path`, `path2`/`newPath`/`new_path`, unambiguous `path`/`uri`/`file*`/`target` pairing, companion `note`); and recovers `edit` match/replace/insert aliases (`old`/`find`/`original`/`match`, string `context` when `oldText`/`pattern`/`range` are absent and replacement text is present, `span`/`marker`/`region`/`anchor`, redundant `op: "replace"\|"edit"`, `new`/`replace`/`patternReplace`, `{ before, after }`, `{ after, insert }`, `{ before, insert }`, `{ start, end }` when `end` matches replacement text, and dummy `range: "0"\|0` alongside non-empty `pattern`/`oldText` and replacement). |
| Regex & matcher tolerances (`MatcherSyntax`) | Lifts leading PCRE inline flags `(?ims)` with a warning; translates Python `(?P<name>...)` and `(?P=name)` and escapes empty code brackets `[]` outside character classes; recognizes unslashed `^`/`$` anchored regexes and unslashed `a\|b` pipe alternations (excluding extglobs and `\|\|`) on `find` and `read`; recovers `~^...` / `~/...` regex-prefixed FTS matchers, `&def symbol`-style declaration prefixes on graph matchers, and non-XPath `//<ident>...` regex patterns on `find` and `read`; folds comma- or pipe-separated `/pattern/` lists on `find` and `read` into alternation while refusing sed ranges (`/a/,+N`, `/a/,-1`, `/a/,`, `/a/,/b/`); escapes unescaped interior `/` inside closed `/pattern/flags` on `find` and `read`; diagnoses trailing text after `/pattern/flags`; recovers unclosed `/pattern` at EOL; and on `edit`, normalizes unreadable single-line literal code patterns starting with `//`, `$`, `&`, or `/` into exact literal matchers. |
| Scope & anchor tolerances (`ScopeSyntax`) | Lifts inline `<L,M>` ranges from `path<L,M>` strings with a warning; recovers singular `line`, bare `edit` anchors (`@abcde`), `42<@abcde>`, quoted range strings (`"\"-1,1,-1,1\""`), `L<N>` / `L<N>-L<M>` and `#<N>,<M>` markers, stray trailing `@` (`"1240,1242@"`), missing second `@` (`"@qAVg2,qAVg2"`), trailing commas (`"17,18,"`), unbalanced angle brackets (`"<@abcde,@fghij"`), anchor-first column tuples (`"@SL,@EL,SC[,EC]"`), packet-header line counts (`"N lines"`), and unambiguous open-ended Python slices (`"-K:"` / `"[-K:]"` as `"-K,-1"` and `":M"` / `"[:M]"` as `"1,M"`), while refusing ambiguous `line:col` or positive/two-sided colon slices with explicit `startLine,startCol,endLine,endCol` (`endCol` exclusive) and `"-K,-1"` recovery. |

## §parser-build Consumer boundary, build projection, and installation gate

| Boundary | Contract |
| --- | --- |
| Importers | Only the service's execution path (`plurnk-core`, `plurnk-acp`, `plurnk-mcp`, `plurnk-execs`) imports `@plurnk/plurnk-parser`; `@plurnk/plurnk-contracts` and `@plurnk/plurnk-providers` declare no dependency on `@plurnk/plurnk-parser`, `xpath`, or `json-p3`. |
| Build & tarball smoke | `npm run build` compiles `dist/` cleanly; `npm run test:installation` packs `@plurnk/plurnk-contracts` and `@plurnk/plurnk-parser`, installs them in a clean consumer, and verifies `PlurnkParser`, `parsePath`, the `plurnk-parser` CLI, and `esbuild` browser bundling. |
